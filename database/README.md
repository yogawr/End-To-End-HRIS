# Recruitment database setup

1. Create an empty MySQL/MariaDB database with a UTF-8 (`utf8mb4`) collation.
2. Copy the database credentials into the project `.env` file:

```dotenv
CI_ENVIRONMENT = production
app.baseURL = 'https://yogawahyu.com/'
database.default.hostname = localhost
database.default.database = nama_database
database.default.username = nama_user
database.default.password = password_database
database.default.DBDriver = MySQLi
database.default.charset = utf8mb4
database.default.DBCollat = utf8mb4_general_ci
database.default.port = 3306
```

3. Use either `php spark migrate` (runs both recruitment migrations, including integrity constraints) or import `recruitment.sql` through phpMyAdmin. Do not use both on the same empty database. The SQL file drops and recreates only `candidates`, `recruitment_jobs`, `candidate_profiles`, and `job_applications`, so export those tables first if they contain data.
4. Ensure `writable/`, `writable/session/`, and `writable/uploads/` are writable by the web server. Uploaded CV files are stored outside `public/`.
5. Point the hosting document root to this project's `public/` directory and enable URL rewriting from `public/.htaccess`.

6. In Niagahoster, select PHP 8.2 or newer and enable `mysqli`, `mbstring`, `intl`, and `fileinfo`. Upload the `vendor/` directory generated by `composer install --no-dev --optimize-autoloader`; it is required because this project does not include vendor dependencies in source control.
